# Цепные звёздочки в Geomwright Studio

Этот документ описывает текущий экспериментальный модуль `chain_sprocket`:
каталог, host-side preview и управляемое создание функциональной звёздочки в
KOMPAS. Он не описывает сборку всей цепной передачи.

## Принятые решения

### Модули

Втулочные и роликовые цепи относятся к одному модулю. Их стандарт, семейство и
размерный профиль выбираются в одном иерархическом селекторе; число рядов
задается отдельным параметром. Отдельные генераторы для этих вариантов не
нужны.

Пластинчатые зубчатые цепи (silent / inverted-tooth chains) относятся к
отдельному модулю. Их зацепление и профиль звездочки принципиально отличаются
от втулочно-роликовых цепей.

Первоначальная карта модулей:

```text
Цепные передачи
├── Втулочно-роликовая цепь
│   └── тип: втулочная | роликовая
└── Пластинчатая зубчатая цепь
```

Двухшаговые роликовые цепи по ISO 1275 — возможное последующее расширение, а
не часть первого объема.

Первый реализованный срез — `chain_sprocket` в Studio. Он предоставляет
каталог коротких цепей ISO 606 серий A/B и размерные ряды ГОСТ 13568
(`ПР`, `ПВ`, `ПРИ`), а также end-view preview функционального
венца. Стандарт определяется через иерархию `стандарт → рядность/семейство → профиль`,
а в прямом API многорядность дополнительно сохраняется в `row_count` для
совместимости; Studio выводит её из выбранного семейства. В API сохраняется конечное
обозначение профиля. В дерево также включены семейства ГОСТ 21834 `НП`, `ТП`.
CAD-построение включено для однорядного функционального венца. Host-side preview
рассчитывает теоретический профиль впадины по отдельным правилам ISO 606 и ГОСТ
591, а Layer 3 строит цилиндрическую заготовку, один сквозной вырез и круговой
массив. Живое создание, сохранение и reopen-readback в KOMPAS подтверждены для
ISO и ГОСТ.

Для профилей по ГОСТ 591 модуль отдельно хранит вариант впадины: со смещением
центров дуг или без смещения. По умолчанию выбран профиль со смещением,
рекомендованный стандартом для обычных передач; вариант без смещения предназначен
для особо точных кинематических и реверсивных передач. Переключатель показывается
только для семейств ГОСТ 13568 и ГОСТ 21834 и не применяется к ISO 606. Расчётное
расстояние между центрами половин посадочной дуги равно `e = 0,03t` либо нулю
соответственно; центры располагаются симметрично на `±e/2` относительно оси
впадины. Контур состоит из рассчитанной посадочной дуги, касательно сопряжённой
боковой дуги и перехода к окружности выступов.

ISO 606 не задаёт аналогичный выбор «со смещением / без смещения». Его профиль
симметричен относительно радиальной оси впадины и задаётся допустимым полем
посадочного радиуса `rᵢ`, радиуса боковой поверхности `rₑ` и угла посадочной
дуги, а также диапазоном наружного диаметра. Для детерминированного
репрезентативного preview используются середины этих диапазонов; допустимые
минимумы и максимумы сохраняются в расчётном результате.

Строка `081` хранится отдельно от `08B-1`: при одинаковом шаге 12,7 мм у них
разные диаметр ролика и внутренняя ширина (`7,75 × 3,3` против `8,51 × 7,75`).
Для `081` предусмотрен явный режим совместимости с нативным модулем KOMPAS:
размеры цепи берутся из строки ISO 606-94, а радиальный контур зуба повторяет
применённую KOMPAS конструкцию ГОСТ 591-69 без смещения. Рабочий контур содержит
восемь дуг и четыре отрезка; ширина зуба равна `0,93 Bвн − 0,15`. Это свойство
записано в метаданных конкретного профиля и не меняет общую midpoint-стратегию
остальных ISO A/B.

### Граница генератора звездочки

Модуль цепной передачи генерирует только функциональную геометрию звездочки:

- профиль и массив зубьев;
- шаговый, наружный и корневой диаметры по выбранному стандарту;
- ширину функционального венца;
- направляющие элементы только в той мере, в какой они являются частью
  конкретной цепной схемы.

Следующие элементы намеренно **не входят** в модули генерации механических
передач:

- ступицы;
- центральные отверстия и расточки;
- шпоночные пазы;
- валы и прочие интерфейсы сопряжения;
- фаски, скругления и другие последующие производственные операции, если они
  не являются частью нормативного профиля зацепления.

Они добавляются отдельными операциями поверх результата генератора. В итоге
модель строится как цепочка независимых операций с явными ссылками на
предыдущий результат:

```text
функциональная звездочка
    → ступица
    → отверстие / расточка
    → шпоночный паз
    → прочие операции
```

Это правило сохраняет звездочку пригодной для повторного использования и не
смешивает механику передачи с универсальными операциями обработки детали.

## Нормативные семейства

Для втулочно-роликового модуля базовыми стандартами являются ISO 606, ГОСТ
13568-2017 и ГОСТ 21834-87. Внутри них используются семейства ISO `A`/`B`,
ГОСТ 13568 `ПР`/`ПРИ`/`ПВ` и ГОСТ 21834 `НП`/`ТП`; расчёт построения
звёздочки по российской системе задан ГОСТ 591-69. Текущий каталог содержит
187 размерных записей: 70 ISO, 43 ГОСТ 13568 и 74 ГОСТ 21834.
Для ISO многорядность вынесена в семейства `A-1/A-2/A-3` и `B-1/B-2/B-3`;
ГОСТ 13568 покрывает таблицы ПР, ПВ и ПРИ, включая многорядные 2ПР/3ПР/4ПР
и 2ПВ; ГОСТ 21834 покрывает НП/ТП с шагами 25,4–63,5 мм и нормативной
рядностью до 8. Размеры цепи, семейство и число рядов хранятся отдельно от
стратегии построения профиля звездочки.

ISO 606 A и B используют одну стратегию построения зубовой впадины, но не один
набор размеров: при одинаковом шаге диаметры ролика/втулки и ширины могут
отличаться. ГОСТ 591-69 имеет отдельную стратегию и два описанных выше варианта;
это атрибут стратегии построения зуба, а не семейство цепи. Preview строит
расчётный теоретический контур обеих систем. Принятые однорядные ISO/GOST
варианты и совместимый `081` подтверждены созданием и reopen-readback в KOMPAS.

Для зубчатого модуля первым российским путем являются ГОСТ 13552 и ГОСТ
13576. Международные профили DIN 8190/8191 и ASME B29.2M следует подключать
через адаптер профиля, не смешивая их параметры с ISO 606.

Обозначение стандарта является частью входного контракта. Размеры из разных
нормативных систем нельзя молча объединять в одну строку каталога.

Локальный профиль цепи KOMPAS (`default.chai_rol_dat`) подтверждает такую
модель данных: `NTDChain` хранит нормативный документ, `TC` — тип цепи (для
примера `PR`), а `Quan_Row` — число рядов. Поэтому `row_count` не зашивается
в семейство или геометрию радиального профиля.

## Текущая реализация

В Studio при выборе нескольких рядов рядом с торцевым видом появляется осевая
схема со штриховкой, номерами рядов и размерами `b` (ширина зубчатого венца),
`A` (межрядный шаг), `B` (общая ширина). На узком экране виды располагаются друг
под другом. Ширина b рассчитывается по табл. 2 ГОСТ 591-69 и не подменяется
расстоянием между пластинами цепи. Для 08A и 08B межрядный шаг подтверждён
таблицей А.1 ГОСТ 13568-97 (ИСО 606-94), для многорядных ПР/ПВ используются
размеры таблицы 2 ГОСТ 13568-97, а для НП/ТП — размерная таблица ГОСТ 21834-87.
ANSI-нумерованная A-серия 25A–240A использует отдельную таблицу ANSI B29.1 с
точным переводом `Pt` и `h2` из дюймов в миллиметры.
Каталог всех публикуемых многорядных строк теперь содержит подтверждённые
осевые размеры; отсутствие `A/h` остаётся общей fail-closed проверкой для
будущих расширений. Диаметр соединительного обода
рассчитывается по таблице 2 ГОСТ 591-69 и передаётся в осевой preview; он
остаётся условным только у строк без высоты пластины. При одном ряде
дополнительная панель скрывается.
Для узких межрядных зазоров, включая 05B, нормальный `r4` остаётся
предпочтительным, но при невозможности разместить две равные галтели выбирается
максимальный вписанный радиус с десятипроцентным центральным поясом; выбор
фиксируется в CAD-плане как `width_fitted_10_percent_land`.
Полная host-side матрица проверяет 215 профилей и все `z=6…200`; сочетания, у
которых соседние ветви `r2` пересекаются раньше наружной окружности, отклоняются
до CAD-записи вместо построения острой вершины. Live KOMPAS подтверждает узкий
ISO 05B-2, крайний ISO 240A-3 и Studio-путь ISO 40A-2.
ПРИ имеет отдельную ветку совместимости: ГОСТ 13568-2017 задаёт размеры
цепи ПРИ, но ГОСТ 591-69 ограничивает таблицу зубового профиля значением
`lambda <= 2`, тогда как ПРИ выходит за этот диапазон. Для этих четырёх
типоразмеров генератор использует подтверждённое нативным модулем КОМПАС
правило `K=0,532` как явно помеченный extended-профиль. Пять наружных диаметров
ПРИ-78,1-360 (`z=25/40/60/90/120`) и по одному диаметру при `z=60` для остальных
ПРИ воспроизводятся этой формулой до отображаемых 0,01 мм. ПРИ-78,1-400 с
`lambda=1,9525` остаётся в обычной верхней строке ГОСТ 591 с `K=0,565`.
Layer 2 дополнительно требует, чтобы наружная окружность встретила обе ветви
`r2` раньше их взаимного пересечения в соседних впадинах. Это сохраняет
шестидуговой профиль, непрерывный preview и притуплённую вершину после полного
кругового массива; compatibility-правило не объявляется нормативной геометрией
ГОСТ 591.
Управление сворачиванием расположено на постоянном разделителе, вне скрываемой
панели. После сворачивания остаётся узкая полоса с названием вида и стрелкой
раскрытия; основной вид занимает освободившееся место. Для вертикальной
компоновки стрелки направлены вверх/вниз. Изменение параметров не сбрасывает
выбранное состояние; анимация не используется.

Начинать следует с конфигуратора в Studio, но не как с отдельного временного
UI-прототипа. Сначала нужно определить детерминированный host-side контракт
модуля и его preview, затем сразу подключить к нему CAD plan. После этого
строится минимальный CAD vertical slice.

Рекомендуемая последовательность:

1. Втулочно-роликовый модуль: схема входа, каталог ISO/ГОСТ, нормализация,
   preview профиля звездочки и диагностические предупреждения.
2. CAD plan без COM-записи: расчет геометрии, контроль размеров и план
   операций функциональной звездочки без ступицы и отверстий.
3. CAD create в новом управляемом документе KOMPAS с readback профиля,
   количества зубьев, шага, диаметра и положительного тела.
4. Отдельные операции над готовой звездочкой: ступица, отверстие, паз и их
   композиция поверх результата.
5. Пластинчатая зубчатая цепь как отдельный Studio/CAD-модуль с собственным
   каталогом и адаптерами профиля.

Первые три шага выполнены для однорядной звёздочки: CAD-план использует настоящие
касательные дуги, Studio предоставляет build-команду, а KOMPAS readback проверяет
замкнутость эскиза, количество зубьев, rebuild и положительное единое тело.
Формулы рабочих дуг и смещения воспроизводят построение ГОСТ 591-69, совместимое
с результатом KOMPAS. Локальный профиль `default.chai_rol_dat` использовался как
источник структуры каталога и полей, но не как источник технического замыкания
эскиза. Внешняя нерабочая часть принадлежит нашему CAD-плану и состоит только из
двух коротких вертикальных выходов и одной горизонтальной перемычки за наружным
диаметром; нативной геометрией зуба она не считается. Уровень перемычки равен
наружному радиусу плюс 0,5 мм, поэтому она гарантированно не пересекает заготовку.
Её длина показывается справочным размером ширины между боковыми линиями.
В схеме со смещением дно впадины образует общая нижняя касательная к двум
посадочным дугам. Нативный модуль разделяет её на две соосные половины; наш
параметрический эскиз использует один отрезок длиной `e`, горизонтальность и
касательность с обеих сторон, без независимого размера длины. Дуги обрезаны до
точек касания, поэтому бугорок их прежнего пересечения отсутствует. При `e=0`
отрезок не создаётся.
Для переходных точек мастер-дуг к боковым линиям сохранён CAD-кандидат с одним
`point_on_curve`: начальная точка правой технической линии связана с наружной
окружностью. Основной bridge-вызов не вернулся за 90 секунд, однако независимый
readback обнаружил ограничение типа 2 и состояние эскиза `fully_defined`; контур
замкнут, без разрывов и самопересечений. После сохранения и повторного открытия
связь сохранилась; один автоматический readback сообщил `under_constrained`,
но пользователь открыл сохранённый файл в видимом KOMPAS и подтвердил полную
определённость эскиза. Проба не требовала видимого экземпляра приложения, поэтому
прежний вывод о потере определённости не подтверждён. Рабочий workflow теперь
строит blank, вырез и массив, затем изолированно добавляет эту связь и отдельным
readback проверяет фактическую пару объектов и топологию контура. Полный вариант
успешно построен, перестроен и сохранён в видимой сессии KOMPAS.
Многорядное CAD-построение доступно при наличии в каталоге поперечного шага и
высоты пластины. ISO A/B использует приложение А, табл. А.1 ГОСТ 13568-97
(ИСО 606-94); отдельные старые ISO-профили 10A/12A/16A и далее не подменяются
записями с ANSI-нумерацией. Осевые данные применяются только при одновременном
совпадении шага, диаметра ролика и внутренней ширины. Многорядные ПР/ПВ используют
собственную табл. 2 основной части ГОСТ 13568-97. Ширина отдельного венца
берётся по табл. 2 ГОСТ 591-69. После построения первого венца со скруглениями
массив тел по сетке копирует его вдоль −X; затем отдельное вращение соединяет
венцы ободом. Его диаметр `Dc = floor(t*cot(pi/z) − 1,3h)` выбран по табл. 2
и правилу округления п. 1.5. Число рядов и шаг массива связаны с `CH_N`, `CH_A`,
общая ширина — `(CH_N−1)*CH_A+CH_B`. Проверяются координаты каждого ряда,
объединение в одно тело, общая ширина и объём. При отсутствии каталожных размеров
запрос останавливается до COM. Для 08B-2, Z25, подтверждены создание и чтение
сохранённой модели: b=6,825 мм, A=13,92 мм, B=20,745 мм, Dc=85 мм.
Для 08B-3, Z25, дополнительно подтверждены три ряда, общая ширина 34,665 мм,
единое тело, формулы массива и полная определённость эскиза обода после открытия.
Сопряжения соединительного обода с венцами скругляются одной операцией по
`2*(n−1)` внутренним кольцевым рёбрам. По табл. 2 ГОСТ 591-69 радиус r₄ равен
1,6 мм при шаге цепи до 35 мм включительно и 2,5 мм при большем шаге. До COM
проверяется место для двух скруглений в каждом промежутке и радиальный запас
до впадин зубьев. Проверка отличает добавление материала во внутреннем углу от
снятия материала на торце зуба. Для 08B-3, Z25, сохранение и повторное открытие
подтвердили четыре сопряжения r₄=1,6 мм, прежние габариты и одно твёрдое тело.
Дополнительно подтверждены 10A-3, Z25, и 4ПР-38,1-508, Z25. Последняя модель
проверяет четыре ряда, шесть внутренних сопряжений и ветвь r₄=2,5 мм.

Торцевые закругления зубьев входят в функциональную звёздочку. После кругового
массива строятся два выреза вращением по осевым профилям черт. 3 и табл. 2
ГОСТ 591-69: `r₃ = 1,7Dц` (минимальный радиус), `h₃ = 0,8Dц` (расстояние
от вершины до линии центров дуг). Это не обычное скругление выбранных рёбер.
Каждый профиль содержит дугу и три замыкающих отрезка; радиус, положение центра
и высоты связаны с переменными детали. Вырезы направлены внутрь заготовки от
торцов `X=0` и `X=−CH_B`. Проверяются уменьшение объёма после каждого выреза,
одно твёрдое тело, замкнутость профилей и сохранение операций после открытия файла.
Для узких венцов радиус увеличивается, чтобы сохранить площадку между дугами
не уже 20% ширины венца. Это явно принятое правило генератора, а не размер,
предписанный ГОСТ. Минимальный радиус сохраняется при `b >= 0,5Dц`; иначе
выбирается `r₃ = h₃²/(0,8b) + 0,2b`, что следует из геометрии окружности
при осевой стреле каждой дуги `s=0,4b`. Ширина венца и h₃ не меняются,
выбранный радиус не меньше нормативного. Формулы и условие выбора сохранены
в переменных CAD. Для 081, Z25, подтверждены создание, сохранение и чтение:
`b=2,919 мм`, `r₃=17,044916820829 мм`, площадка `0,5838 мм`; оба осевых эскиза
полностью определены после повторного открытия.
Для ISO 08A-1, Z25, построение и чтение сохранённого
результата подтверждены; `r₃=13,515 мм`, `h₃=6,36 мм`.

Рабочие источники для текущего сравнения: [ISO 606:2015](https://www.iso.org/standard/61232.html),
[ГОСТ 591-69](https://files.stroyinf.ru/Index2/1/4294823/4294823321.htm),
[ГОСТ 13568-2017 (PDF)](https://files.stroyinf.ru/Data2/1/4293733/4293733500.pdf),
[ГОСТ 21834-87 (PDF)](https://files.stroyinf.ru/Data2/1/4294831/4294831887.pdf), а для
сводной таблицы размерных рядов — [BS/ISO 06B–32B](https://mechcodex.com/reference/roller-chain-dimensions-bs-iso)
и [ANSI/ISO A](https://mechcodex.com/reference/roller-chain-dimensions-ansi).
Последние два источника используются как справочная сверка и не заменяют
текст действующего стандарта перед CAD-реализацией.

Такой порядок позволяет рано проверить пользовательский контракт, каталог,
preview и нормализацию без блокировки на деталях COM, но сохраняет тот же
контракт для последующего CAD-построения.

## Layer и проверка

Полный генератор звездочки — Layer 4. Его внутренние расчетные правила и
нормализация — Layer 2, а последовательность CAD-операций с preflight,
readback и correction — Layer 3.

Редактирование уже созданной звёздочки, пластинчатые цепи, ремни, ступицы,
расточки, шпоночные пазы и автоматическая сборка нескольких деталей остаются
за пределами этой версии.

Успешный preview не считается доказательством корректности CAD-модели. Для
законченного модуля обязательны:

- проверка профиля и инвариантов на host-side;
- readback созданных операций и основных размеров;
- проверка единого положительного тела;
- сохранение и reopen-readback для принятой версии генератора.
