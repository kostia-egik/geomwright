# Straight bevel wheel

[Русский](../ru/gear-bevel.md) · [English index](README.md) · [Detailed contract](../gear-bevel.md)

Status: experimental, implemented create-only module. It calculates a nominal
Tredgold projection and creates one straight bevel wheel with a dish blank.
It does not calculate a gear pair, contact, strength or cutter-generated flanks.
`tooth_type="circular"` is reserved and rejected.

## Inputs and resolved defaults

| API field | Contract |
| --- | --- |
| `standard` / `modification` | Default `gost_13754_68` / `standard`; five rack systems are accepted, listed below |
| `module_mm` | Outer circumferential module; default 3 mm, selected from supported module rows |
| `tooth_count` | Default 20; 6–400 |
| `pitch_cone_angle_deg` | Half-angle; default 45°, range 5–85° |
| `profile_shift` | Default 0; schema range −1.5…1.5 |
| `face_width_mm` | Omitted: `b = 0.285 R_e`; `b / R_e > 0.3` produces a warning; `b >= R_e` is rejected |
| `rim_back_extension_mm` | Omitted: `max(2 mm, 1.2 b sin δ)` in the calculation |
| `rim_front_extension_mm` | Omitted: `max(1.5 mm, 0.3 b sin δ)` |
| Rack coefficients | Explicit values only with `modification="custom"` |

Rack systems: ГОСТ 13754-68, ГОСТ 13755-2015, ГОСТ 9587-81, ГОСТ Р 50531-93 and
ISO 53:1998. Call `list_gear_standards` for identifiers, variants and module rows.
Schema ranges do not guarantee geometric feasibility; inspect preview errors
and warnings before creating CAD.

Dish-blank extensions are body-shape heuristics, not normative basic-rack
dimensions. The schema, calculation and Studio hints use the same defaults.

## MCP workflow

Alternatively, use the shared MCP/CLI contract with `module_id="gear_bevel"`
and one action: `preview`, `plan`, `create` or `inspect`. Obtain its schema
with `get_cad_module_contract`; [README](../../README.md#cad-module-pilot-mcp-and-cli)
has the JSON envelope and CLI commands. Creation requires `confirm_write=true`.
Inspect is recipe recognition, not a fresh geometry audit; recreate only when
`data.recreatable=true`. Face width is along the pitch cone, not axial thickness.

Preview request for `preview_bevel_gear`:

```json
{
  "request": {
    "tooth_type": "straight",
    "standard": "gost_13754_68",
    "modification": "standard",
    "module_mm": 3,
    "tooth_count": 20,
    "pitch_cone_angle_deg": 45
  }
}
```

1. Preview without COM; check `success`, errors, dimensions and resolved rim extensions.
2. Pass the same request to `create_bevel_gear` with `execute=false` to inspect
   the numeric CAD plan.
3. To create a new part, set both `execute=true` and `confirm_write=true` inside
   `request`, after configuring the visible CAD session.
4. Read the returned verification and exact document ID. Save/reopen as required,
   then call `inspect_bevel_gear` with that ID to read the block and recipe.

Creation revolves the dish profile about global X, cuts one tooth space between
two cone-normal sections and patterns it `z` times. The calculation reports
`warning.gear_bevel_nominal_projection`: this is a virtual-gear projection,
not exact spherical involute or an octoid generated by a real cutter.

Studio exposes the same module in its gear group. A saved recognized block
restores inputs for a new build; it does not provide in-place parameter editing.
Hubs, bores, keyways, tip chamfers and application to an existing body are outside
this module's contract.

## Evidence and limits

The detailed contract records two live creation/save/reopen cases and describes
single-solid, bounds, tooth-count and volume checks (1.5% acceptance tolerance).
The evidence artifacts are local and ignored. The 2026-10-07 audit reran host
checks and Studio visual checks, but did not repeat live creation/save/reopen
after the fixes. Recorded cases are not fresh validation of every input or
certification of tooth contact/strength.

On 2026-10-09 the default `m3 z20 delta45` case passed shared-MCP creation,
native order-4 knot/weight readback and save/reopen recipe parity after correcting
section-frame order conversion (`CURVE-001`). Simple-knot C2 spline sections
then reduced the face count from 743 to 183 and creation from about 92 to 30
seconds locally, with the same bounds and unchanged acceptance tolerance
(`CURVE-002`). This is fresh acceptance of that case, not every input combination.

The end contour intersects projection rays with the back cone rather than its
tangent plane. Studio displays three coordinated views:

- Left: the rim sector along the axis, including the solid foundation below the teeth,
  with longitudinal tooth edges and central tooth marked D without color highlighting.
  Teeth remain visible through the small end. The bottom wavy break passes
  through the foundation below the inner tooth contour, not through the teeth.
  Thin gray longitudinal lines mark the root-to-transition boundaries of each gap.
- Upper right: the hatched radial half of the axial section, with apex O,
  dimensions `B`, `b`, `Rₑ`, cone angles and viewing direction D.
- Lower right: the enlarged large-end view of tooth D along its pitch generator.
  This projects the actual conical end; it is neither a section nor the virtual
  wheel profile. `sₑ,proj` is the projected pitch chord; head/root heights belong
  to the central generator, not to chordal inspection heights.

Thin wavy break lines crop the bottom and sides of the sector and View D.
They trim drawing fills and lines without changing tooth geometry or the CAD
plan. Real edges retain their ordinary contours; the axial section is not cropped.

The right views collapse together and appear below the sector on narrow screens.
Circular teeth will require their own calculated longitudinal curves; they are
not currently built or depicted by bending the straight-tooth drawing. Rejected geometry
shows errors and disables CAD creation. Tooth control measurements describe the
nominal virtual gear. Volume uses a sampled contour with analytical integration
along scaled rays; it is an estimate, not an exact BREP result.

Without virtual-gear undercut, the root transition meets the involute at an
analytical tangency station. Local sampling retains the rounded transition at
large cone angles. Undercut profiles keep sharp-rack intersection trimming.
A tabulated rack tip radius supplies a rounded-tip envelope for non-undercut
profiles without changing root depth or the straight rack flank. Missing radii
retain the sharp tip. This remains a nominal Tredgold projection, not an octoid
generated by a real bevel cutter.
