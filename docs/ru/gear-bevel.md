# Прямозубое коническое колесо

[English](../en/gear-bevel.md) · [Русский индекс](README.md) · [Подробный контракт](../gear-bevel.md) (EN)

Статус: экспериментальный реализованный create-only модуль. Он рассчитывает
номинальную проекцию Тредгольда и создаёт одно прямозубое коническое колесо с
тарельчатой заготовкой. Расчёт пары, контакта, прочности и поверхности от реального
инструмента в контракт не входит. `tooth_type="circular"` зарезервирован и отклоняется.

## Входные данные и вычисленные defaults

| Поле API | Контракт |
| --- | --- |
| `standard` / `modification` | По умолчанию `gost_13754_68` / `standard`; принимаются пять систем исходного контура, перечисленных ниже |
| `module_mm` | Внешний окружной модуль; по умолчанию 3 мм, из поддержанных рядов модулей |
| `tooth_count` | По умолчанию 20; 6–400 |
| `pitch_cone_angle_deg` | Полуугол; по умолчанию 45°, диапазон 5–85° |
| `profile_shift` | По умолчанию 0; диапазон схемы −1.5…1.5 |
| `face_width_mm` | Если не задано: `b = 0.285 R_e`; при `b / R_e > 0.3` выдаётся предупреждение; `b >= R_e` отклоняется |
| `rim_back_extension_mm` | Если не задано: `max(2 мм, 1.2 b sin δ)` в расчёте |
| `rim_front_extension_mm` | Если не задано: `max(1.5 мм, 0.3 b sin δ)` |
| Коэффициенты исходного контура | Явные значения только с `modification="custom"` |

Системы контура: ГОСТ 13754-68, ГОСТ 13755-2015, ГОСТ 9587-81, ГОСТ Р 50531-93 и
ISO 53:1998. Вызовите `list_gear_standards` для идентификаторов, вариантов и рядов
модулей. Диапазон схемы не гарантирует геометрическую реализуемость: изучите
ошибки и предупреждения preview до создания CAD.

Припуски тарельчатой заготовки — эвристики формы тела, а не нормативные размеры
исходного контура. Схема, расчёт и подсказки Studio используют одинаковые defaults.

## MCP-workflow

Также доступен общий MCP/CLI-контракт с `module_id="gear_bevel"` и одним из
действий `preview`, `plan`, `create`, `inspect`. Схему выдаёт
`get_cad_module_contract`; формат JSON и CLI-команды описаны в
[README](../../README.md#cad-module-pilot-mcp-and-cli). Для создания требуется
`confirm_write=true`. Inspect распознаёт рецепт, не проверяя геометрию заново;
повторное построение допустимо только при `data.recreatable=true`.
Ширина венца измеряется вдоль образующей конуса, а не вдоль оси X.

Preview-запрос для `preview_bevel_gear`:

```json
{
  "request": {
    "tooth_type": "straight",
    "standard": "gost_13754_68",
    "modification": "standard",
    "module_mm": 3,
    "tooth_count": 20,
    "pitch_cone_angle_deg": 45
  }
}
```

1. Выполните preview без COM; изучите `success`, ошибки, размеры и вычисленные припуски.
2. Передайте тот же request в `create_bevel_gear` с `execute=false`, чтобы прочитать
   числовой CAD-план.
3. Для создания новой детали задайте внутри `request` одновременно `execute=true`
   и `confirm_write=true`, предварительно настроив видимую CAD-сессию.
4. Прочитайте verification и точный ID документа в ответе. Сохраните/переоткройте
   по контракту, затем вызовите `inspect_bevel_gear` с этим ID для чтения блока и recipe.

Построение вращает тарельчатый профиль вокруг global X, вырезает одну впадину
между двумя нормальными к конусу сечениями и повторяет её `z` раз. Расчёт выдаёт
`warning.gear_bevel_nominal_projection`: это проекция виртуального колеса,
а не точная сферическая эвольвента или октоида от реального инструмента.

Studio предоставляет тот же модуль в группе зубчатых передач. Сохранённый
распознанный блок восстанавливает параметры для нового построения; редактирование
параметров существующего блока не поддерживается. Ступицы, отверстия, шпонки,
фаски зубьев и применение к существующему телу находятся вне этого контракта.

## Доказательства и ограничения

2026-10-09 вариант по умолчанию `m3 z20 delta45` прошёл создание через общий MCP,
readback порядка 4, узлов и весов кривых, сохранение и восстановление рецепта после
исправления передачи порядка при преобразовании сечений (`CURVE-001`). Переход
на C2-сплайны с одиночными внутренними узлами уменьшил число граней с 743 до 183,
а время создания — примерно с 92 до 30 секунд на этой машине. Габариты и допуск
приёмки не изменились (`CURVE-002`). Это свежая проверка одного варианта,
а не всех сочетаний входных данных.

Подробный контракт содержит два сохранённых случая live creation/save/reopen
и описывает проверки одного тела, bounds, числа зубьев и объёма (допуск проверки
1.5%). Артефакты локальные и ignored. Аудит 2026-10-07 повторил host-проверки и
визуальные проверки Studio, но не live creation/save/reopen после исправлений.
Сохранённые случаи не являются свежей проверкой всех входных данных или
сертификацией контакта/прочности.

Торцовый контур пересекает лучи проекции с задним конусом; это не проекция его
касательной плоскости. Studio показывает три связанных вида:

- Слева — сектор венца вдоль оси со сплошным телом основания под зубьями.
  Видны продольные границы зубьев; центральный зуб отмечен D без цветового выделения. Опорная тарелка
  продолжается внутрь: зубья видны до малого торца, а нижний волнистый обрыв
  проходит по основанию ниже внутреннего контура зубьев.
  Серые продольные линии обозначают границы перехода от дна впадины к скруглению.
- Справа сверху — радиальная половина осевого разреза со штриховкой, вершиной O,
  размерами `B`, `b`, `Rₑ`, углами конусов и направлением взгляда D.
- Справа снизу — увеличенный вид большого торца зуба D вдоль его делительной
  образующей. Это проекция фактического конусного торца, не разрез и не профиль
  виртуального колеса. `sₑ,proj` — хорда в этой проекции; высоты головки и ножки
  относятся к центральной образующей, а не к хордовым контрольным высотам.

По низу и бокам сектора и вида D проходят тонкие волнистые линии обрыва.
Они обрезают изображение и заливку, не меняя геометрию зубьев или CAD-план.
Реальные кромки остаются обычными контурами; осевой разрез не обрезается.

Правые виды скрываются вместе, на узком экране размещаются ниже сектора.
Для кругового зуба потребуются его расчётные продольные кривые; сейчас он
не строится и не изображается условным изгибом прямого зуба. При отказе
расчёта показывает ошибки и блокирует создание CAD. Контрольные измерения зуба
относятся к номинальному виртуальному колесу. Объём вычисляется по дискретному
контуру с аналитическим интегрированием масштаба; это оценка, не точный BREP.

Без подрезания виртуального колеса переходная кривая впадины стыкуется с
эвольвентой в аналитически рассчитанной точке касания. Локальная дискретизация
сохраняет округлый участок и при больших углах конуса. Для подрезанных профилей
сохраняется обрезка по пересечению остроконечной рейки. Если радиус вершины
рейки задан в исходном контуре, для неподрезанного профиля рассчитывается
огибающая скруглённой вершины: глубина впадины и прямая сторона рейки остаются
неизменными. Без заданного радиуса используется острая вершина. Это по-прежнему
номинальная проекция Тредголда, не октоида реального конического резца.
