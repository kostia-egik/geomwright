# Аудит проекта — 2026-10-07

[English](../en/project-audit.md) · [Русский индекс](README.md)

Главный вывод: Geomwright имеет разумные границы между расчётом, workflow и COM,
но до аудита несколько путей ошибочно сообщали успех. Исправлены подтверждённые
дефекты, а не вся архитектура ради другой структуры каталогов.

## Коническое колесо и превью

Модуль строит одно номинальное прямозубое колесо по проекции Тредгольда, не
коническую пару. Расчёт без COM обслуживает MCP, Studio и CAD-план.

Исправлено:

- Торцовый контур пересекает лучи с задним конусом. Раньше проецировалась его
  касательная плоскость, что искажало контур вне делительной образующей.
- Повторение периода больше не проводит замыкающие хорды через каждый зуб.
  Пересечение с окружностью вершин вычисляется как пересечение отрезка и окружности.
- Осевой силуэт не рисует внутреннюю линию по оси. Вид размеряет `b` и полный
  габарит `B`, включая выступающий внутренний угол венца.
- Отказ preview отображается как отказ, с причинами и отключённым CAD. Он не
  попадает в кэш успешных результатов. Переключение языка сохраняет bevel-подсказки.
- Объём учитывает оба конуса, оба плоских торца и запас секций loft. Интегрирование
  вдоль лучей аналитическое; интегрирование дискретного контура — численное.
- Проверяются нечисловые/бесконечные значения, высоты зуба, пересечения и
  реализуемость заготовки. В CAD-плане больше нет повторного полного расчёта.
- Схема, расчёт и подсказки согласованы по default заднего припуска:
  `max(2 мм, 1.2 b sin δ)`. Это эвристика заготовки, не нормативный размер рейки.

Для `m=3, z=20, δ=45°`: `dₑ=60 мм`, `dₐₑ≈64.243 мм`, `b≈12.092 мм`,
`B≈18.205 мм`, расчётный объём `≈33433.499 мм³`.
Уточнение угловой квадратуры с 720 до 2880 отсчётов изменило объём на
0.0000873%. Измеренная медиана построения плана после устранения повторного
расчёта — 0.127 с; один прежний замер — 0.381 с. Это локальные измерения,
не гарантия времени на любой машине.

## Надёжность и эксплуатация

- Отрицательный preflight останавливает создание и последующий readback.
- Bridge выводит stdout/stderr в файлы: большой вывод не блокирует pipes.
  Ошибка callback завершает принадлежащий runner процесс; ненулевой exit code
  не публикуется как успех. Progress читается инкрементально.
- Отказ сохранения не закрывает изменённый документ. Наличие старого файла
  больше не доказывает успешное сохранение. Shutdown не завершает приложение
  при оставшихся документах или неудачном сохранении.
- Неизвестный явный ID не выбирает активный документ; неоднозначное имя
  отклоняется. Для несохранённых документов `runtime_id` использует API7
  Reference, а не индекс коллекции. Старый `@document:N` требует обновления
  списка документов; это намеренный отказ от небезопасного fallback.
- Studio проверяет локальный Host и Origin до вызова маршрута. Браузерные
  изменяющие запросы требуют same-origin; локальные программные клиенты без
  браузерных заголовков сохраняют доступ. Это не аутентификация пользователей.
- Studio принимает одно CAD-задание за раз и сохраняет до 100 завершённых
  записей. Create и update используют общий механизм; лишний поток не создаётся.
- Зависимость MCP закреплена на проверенном диапазоне `>=1.27,<2`.
  CI и локальный quality gate используют независимые deadlines; CI устанавливает
  собранный пакет. Обработка пустого сообщения JUnit исправлена.

## Архитектура, структура и данные

Четыре слоя, отдельный COM-процесс, create-only ограничения и compatibility
фасады имеют практическую пользу. Новая инфраструктура очередей, универсальный
operation graph или массовое переименование namespace здесь не нужны.

Bridge (около 31.6 тыс. строк), `parametric.py` (12.6 тыс.) и adapter (3.6 тыс.)
остаются точками концентрации сопровождения. Размер сам по себе не делает их
разбиение безопасным. Новые самостоятельные области стоит выносить по реальному
владельцу поведения; работающий dispatch не следует дробить механически.

Таблицы стандартов доступны офлайн, реконструкции отмечены как реконструкции.
Нормативная точность и права распространения исходных материалов не
сертифицированы этим аудитом. Источник timing-belt данных с ссылкой на `main`
стоит закрепить на ревизии при следующем обновлении таблицы.

Документация получила согласованные EN/RU страницы знакомства, установки,
архитектуры, разработки и bevel-контракта. Имена тем совпадают; новый язык
добавляется каталогом локали. Подробные исторические страницы пока не все
локализованы. README и канонические архитектурные документы сохраняют свои роли.

## Проверки и границы готовности

Проведены профильные host-тесты геометрии, схем, HTTP, save lifecycle,
bridge subprocess и preflight: 102 теста и 59 subtests прошли за 18.80 с.
Проверены wheel вне checkout, package assets,
регистрация MCP, compile, равенство двух bridge-копий и diff.
Studio проверен в браузере на RU/EN, для успешного и отвергнутого запроса;
изображения просмотрены, а не только сохранены.

API7 Reference прочитан в двух независимых процессах для трёх существующих
документов: значения совпали. Закрытие соседних документов проверено заглушками,
не живым закрытием пользовательских моделей. Reference относится к текущей
сессии; это не постоянный ID для следующего запуска КОМПАС.

После исправлений не повторялось живое создание/save/reopen bevel-модели и не
запускался полный набор CAD-семейств. Установочный smoke не заменяет GitHub CI,
а существующие live-примеры не доказывают корректность всех входных комбинаций.

Итог: модуль пригоден для номинального preview и контролируемого create-only
workflow. До выпуска нужна свежая live-проверка CAD по исправленному плану.
Он не готов как инструмент расчёта пары, контакта, прочности или производственной
сертификации поверхности зуба — этих возможностей в контракте нет.
